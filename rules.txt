JustaPlatformer 프로젝트 규칙

================================
1. 기본 원칙
================================

1. 모든 정보는 추측하지 않는다.

기준:
- 최신 업로드 파일
- 이전 확정 내용
- 현재 확정된 구조

에서만 가져온다.

확인되지 않은 내용은 추가하지 않는다.


2. 가장 최신 데이터를 우선한다.

이전 설계와 현재 파일 내용이 충돌할 경우:
최신 파일 기준으로 수정한다.


3. 오류는 넘어가지 않는다.

발견 즉시:
- 원인 확인
- 수정 방향 결정
- 수정 후 검사

를 진행한다.


================================
2. 파일 관리 규칙
================================

1. 기존 구조를 우선 유지한다.

임의로:
- 파일 추가
- 폴더 변경
- 역할 변경

하지 않는다.

변경 필요 시:
변경 이유를 먼저 확인한다.


2. 파일 역할

objects.js:
오브젝트 정의 및 생성 관련

physics/:
물리 계산 및 적용

chaser.js:
적 AI

item/:
아이템 관련

stage/:
스테이지 관련

setting/:
게임 설정 및 상수

game.js:
게임 전체 연결

ui.js:
화면/UI 처리


================================
3. 코드 작성 규칙
================================

1. 파일명

camelCase 사용.

예:
objectData.js
stageData.js
calculate.js


2. 변수명

camelCase 사용.

예:
objectId
playerSpeed
gravityPower


3. class명

PascalCase 사용.

예:
GameObject
Player


4. 불필요한 내용 제거

삭제:
- 필요 없는 주석
- 과도한 줄바꿈
- 중복 코드


================================
4. 생성 규칙
================================

1. 코드 생성 전 확인

반드시 확인:

- 기존 변수명
- 파일 연결 관계
- 데이터 구조


2. 파트별 생성

분할 생성 시:

- 각 파트는 복붙 가능해야 한다.
- 이전 파트와 연결 가능해야 한다.
- 괄호와 문법을 확인한다.


3. 코드 생성 후 검사

검사 항목:

문법:
- 괄호
- 쉼표
- 함수 닫힘
- 객체 구조

연결:
- 변수명 일치
- 함수 연결
- 파일 역할 충돌


================================
5. 설계 원칙
================================

1. 데이터와 실행을 분리한다.

objectData:
설정 데이터

GameObject:
실제 생성된 객체


2. 계산과 적용을 분리한다.

calculate.js:
계산

physics.js:
적용


3. AI는 별도 관리한다.

enemy 행동은:
chaser.js 등에서 관리한다.


================================
6. 작업 순서
================================

구조 확인
↓
파일 분석
↓
수정 계획 작성
↓
코드 생성
↓
문법 검사
↓
연결 검사
↓
다음 작업 진행


================================
7. 기준 파일 확인
================================

긴 작업 진행 시:

objects.txt
structure.txt
rules.txt

등 기준 파일을 다시 확인한다.
